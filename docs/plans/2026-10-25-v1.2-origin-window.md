# Version 1.2: originating chat and one window per session

The requested changes are to connect a workbench opened from a Codex chat to that same chat by default, and to update an existing paper window instead of opening duplicates during file import. Existing model choice, history, paragraph notes, draft edits and reviewed source-write boundaries must remain intact.

- [x] Reproduce repeated and concurrent open/import calls before fixing the server's shared open promise and reporting window reuse accurately.
- [x] Add an exact-session native window registry. Serialize browser-profile launches across processes; verify window handle, process lifetime and private nonce before reuse. Preserve navigation/caret/geometry, permit reopening after close, and fail closed for uncertain ownership.
- [x] Carry only the host-provided originating chat ID through the signed background descriptor. A random window instance is never a chat identity.
- [x] Verify the exact existing chat through metadata-only thread/read, inherit its actual model/effort, persist a paper-scoped reference and attempt connection after source import. Do not start a model turn, create another chat, interrupt Desktop or replace an explicit different binding.
- [x] Display automatic connection progress and ordinary writer contention without a manual binding prerequisite. Explicit release/advanced overrides remain authoritative.
- [x] Validate the affected paper/chat using private source copies, then verify migration of its actual saved record, all regression suites, installation and a private-data-free 1.2.0 package.

Legacy browser windows have no ownership marker and cannot safely be adopted or closed by title. Close those old duplicate windows once when loading this update; subsequent calls reuse the exact registered window. Desktop may temporarily own the chat writer; binding and identity remain visible while the backend waits without sending extra requests.
