# Reliable repeated editing in v1.5.2

**Goal:** Support repeated author edits and confirmed English writebacks without losing translation text, source identity, the latest PDF, or the existing Desktop chat.

**Architecture:** Confirmed transaction evidence rebases only the exact draft it consumed. A separate authenticated, ephemeral editor channel captures unsaved text on demand; native tools never infer a browser identity from a window title. Rendering and background status refreshes share cached document work, and stable-release checks remain outside the input path.

**Constraints:** No model-controlled source acceptance, no force-clearing genuine conflicts, no new model worker or replacement chat, no private manuscript/history in release artifacts. Public UI and documentation default to English. Updates require an explicit installation confirmation.

Publication follows artifact freezing: publish only audited v1.5.2 source/runtime ZIPs, checksums and English release notes, then compare the public source tree and downloaded assets with those frozen bytes. The GitHub release and its separate delivery receipt record that external step.

## Review focus

- A newer human edit must survive an older save/capture/compile response.
- A changed source without exact confirmed transaction evidence must remain a visible conflict.
- A legacy failed draft must be repairable only when retained history proves its association.
- Multiple windows, hidden pages and interrupted services must never manufacture a fresh capture.
- Missing network, compiler or write permission must preserve text and the previous successful PDF.
