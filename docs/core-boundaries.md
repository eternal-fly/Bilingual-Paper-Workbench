# Bilingual Paper Workbench: Data and Source Boundaries, Version 1.5.1

This document explains source protection, private state and recovery. Start with the [User Guide](USER_GUIDE.md) for normal operation. English is the default interface language; selecting another interface or translation language does not change source authority.

Version 1.5.0 removes author-facing item-count ceilings throughout selection, matching, organization, translation, synchronization, pending revision construction and compatible Desktop callbacks. Unique IDs and exact approved coverage remain mandatory. Byte-adaptive review batches and native result staging preserve caller/source/draft identity; intermediate parts grant no source acceptance and cannot prematurely complete a Desktop request. Only the full validated result publishes. Concurrency and display pagination remain operational controls.

Version 1.4.2 validates imported opinions individually against current paragraph identities and hashes. The original import version remains provenance; explicit local rechecking refreshes only exact provable associations. Changed, missing, ambiguous and unlocated anchors are not silently renewed. Organization may present those opinions against explicitly supplied current context without granting source-location, adoption, draft or write authority. Current callback checks continue to bind the selected opinions and every context actually supplied. An unrelated old opinion cannot block the selected current subset merely through the original batch snapshot.

Version 1.4.1 adds a direct author-click writeback entry in the first PDF column. It uses the existing private UI-only prepare/apply protocol, exact successful isolated build and short-lived one-use token. It does not expose source acceptance to model tools. The current draft revision is revalidated during candidate construction and acceptance, including prose-only changes. Compilation, polling and model results never automatically authorize a write.

Version 1.4.0 adds a whole-paragraph mathematical inventory for complete saved human drafts whose formulas cannot be mapped one-to-one. The backend derives the exact before/after lists and protected inventory from the current paragraph, and pins them to the project, snapshot, source hash, language, draft revision and full draft hash. This is an explicit revision request over an already human-authored draft, not model-created authority. Native requests expose the original source and the review lists. Candidate output must preserve that inventory and the unchanged/effectively-authorized nonmath skeleton; new controls remain bounded and embedded labels/references retain their exact footprints. Draft edits or undo invalidate both pending proposals and compiled confirmations. The earlier per-formula rules below remain the narrower compatibility path; new citation placement is not authorized by a math inventory.

Project selection is a private UI operation over an exact saved record and its verified existing chat. A cross-chat selection uses that chat's canonical daemon, keeping its native callbacks and model history together. The first invocation still derives its identity and roots from the host. Signed context refresh cannot be supplied through a model tool. Window navigation uses a one-use handoff and verifies the browser/process/nonce record before transferring window ownership; its capability URL is never returned through MCP. Missing chat metadata, busy operations and conflicting live window ownership fail without replacing the current paper.

Reference commands remain protected by default. The authenticated whole-paragraph save may derive a separate `referenceEdits` grant for an exact existing standalone citation/cross-reference occurrence. It binds the source token and original bytes, project, snapshot, paragraph, language, current draft revision and exact replacement/deletion. Bibliography and label namespaces are separate. A bounded non-expanding index uses only reachable source/bibliography inputs; ambiguous, dynamic, conditional, macro-body or literal-example identities cannot establish an editable target. Case-colliding bibliography keys are unavailable; label names retain exact case.

Models cannot supply these grants through request/result arguments. Revision packets receive only their validated effective protected values; new requests, proposals and final previews recheck current author authority. Undo/redo revokes or restores an exact full-text history match. Ordinary translation contexts strip private reference history, and translation/review returns preserve active author reference intent. Unknown or incomplete changes fail atomically with the editor buffer retained; a new/ambiguous placement may remain a local unmapped draft without source authority. Source label/tag definitions, command names, optional notes and references nested inside formulas remain fixed. Source promotion still requires exact isolated compilation and human confirmation.

The tested project scope includes the original 18-page REVTeX/pdfLaTeX paper with its figures and BibTeX, and the supported bilingual XeLaTeX template. Successful tests of those inputs do not establish support for arbitrary dynamic TeX. Version-specific receipts and pending release checks are recorded in [Verification](verification.md).

The core reviews a bounded reachable LaTeX input graph. Supplying `mainFile` reads that file and its declared `input`, `include`, bibliography, local class/style and graphics dependencies. It does not recursively inventory the selected directory. Main-file discovery without an explicit filename is bounded to six directory levels and 2,000 entries, excludes hidden/build directories and symlinks, and asks for a choice when there is not exactly one document entry.

Inputs must be regular files inside the selected root. Traversal, absolute dependency injection, reserved Windows names, symlinks, invalid UTF-8 text and case collisions are rejected. Limits are 500 reachable inputs, 4 MiB per input and 32 MiB total. Selected paragraphs, proposals and opinions have no independent record-count ceiling. Registered requests are bounded by 64 MiB; context pages target 2 MiB and tool envelopes use 8 MiB, with exact continuation and staged output for large selections. One indivisible protected record can exceed the page target within its reported transport budget; actual serialized size and the exception are explicit. Whole-PDF review has a separate complete-context limit of 2 MiB and grants no source write authority. These checks are a conservative file proxy, not an operating-system sandbox or a proof against a hostile process racing filesystem reparse points.

Each project identity binds both its canonical root and main file. Sources and candidates use exact SHA-256 hashes. Source ranges are UTF-8 byte offsets; unchanged bytes and CRLF are preserved in candidate construction. Segment IDs are opaque UUIDs. Exact unchanged intervals retain IDs; reviewed apply and inverse transactions additionally preserve identity through their verified byte-delta lineage. External changes without exact lineage may create new IDs; old drafts remain retained and stale. No fuzzy relocation is used.

The lexer never expands TeX. Formulae, citations, references, comments and structural tokens are protected in order. Unknown command blocks remain opaque. Unsafe category-code primitives and redefinitions of lexer-significant commands make automatic editing opaque from that source position onward; preamble assignments therefore affect all body blocks, while later assignments do not retroactively disable earlier prose. Ordinary caption-name or abstract presentation redefinitions do not disable unrelated paragraphs. Explicitly declared zero-argument `newcommand` markers with a bounded body consisting only of a small verified formatting allowlist and literal named colors may prefix editable prose; the marker invocation remains protected. A short static language label may occur inside an explicit font/color formatting group, with at most 16 visible letters, numbers or allowed punctuation and no embedded spaces; it is preserved as part of the marker invocation. Parameterized, unknown, unrestricted text-producing or unsafe macro bodies stay opaque, and later marker redefinitions invalidate later invocations.

One exact declared presentation-environment pattern is supported: `newenvironment` with one required argument, beginning with `\par\begingroup\color{#1}` and ending with `\par\endgroup\smallskip`. Invocation requires a literal named-color argument. Its boundaries remain protected while its ordinary prose can be edited. Unknown bodies, parameters used for other operations, nonliteral colors and unsupported environments remain opaque across paragraph boundaries. This is a tested subset of LaTeX, not a general TeX parser.

v0.4 adds independent literal reading-range authority rather than relaxing those canonical parser rules. A supported English projection supplies original body, heading and caption intervals. `range-authority.mjs` independently verifies exact original UTF-8 bytes, current file/snapshot identity and round-trip protected placeholders. Authority binds the whole-file hash, interval hash, coordinates and protected skeleton, and candidate construction revalidates it. A model or projection cannot provide its own authority. This lets all verified paragraphs of a complex supported paper generate candidates from translation intent, including ranges beyond unrelated macro definitions that made a canonical block opaque. Whole-paper coverage and actual acceptance evidence remain in verification.md.

Complete math environments and fixed macro invocations are opaque protected objects; formatting structure stays protected while safe natural-language arguments can change. Citation keys, formulas, macro parameters, references, comments and object order cannot change through a prose candidate. New TeX syntax, duplicated/reordered/removed placeholders, incomplete controls/groups, unknown dynamic invocations and direct lexical changes are rejected. A small exact allowlist supports standard grouped bibliography URL shims; modified shims and redefined protected commands do not inherit that exception. Unprovable ranges retain drafts/opinions but cannot produce source candidates. Arbitrary TeX expansion is outside this proof.

## Default writing Skill boundary

Only applicable installed writing/translation/polishing guidance is requested by default in the existing Desktop chat. Registered author preferences can prioritize or exclude Skills; imported material cannot activate one. Reading a Skill grants no source acceptance, broader filesystem authority, new conversation or unrelated action. A legacy private model bridge lacking host Skill access must fail honestly before review inference instead of claiming that a Skill was applied. Actual 1.3.0 acceptance independently observed successful Skill entry/style/writing reads in the bound Astra chat.

## Direct native access and display preferences

Version 1.3.1 exposes eight bounded native operations for the current paper: paginated project-index reading, selected protected-paragraph reading, request preparation, translation-task preparation/control, explicit language configuration, and display-preference reading/configuration. The invoking identity comes from the trusted MCP host/daemon envelope, never a model-supplied chat or binding ID. A currently unverified or different origin cannot use a saved binding as a substitute. Project, snapshot, target-language and revision checks apply at the relevant read and serialized commit boundary.

The index is paginated and contains brief location hints rather than full paper text. Exact reads and prepared batches use complete protected records and byte-driven pagination. Native response guidance is included in the context budget; continuation offsets preserve full scope. Large output parts remain inert until complete result validation and atomic publication. Whole-paper tasks retain their approved selection privately and return compact task identities. Private formula history, UI capabilities and source-confirmation material are excluded from these new interfaces.

Direct native preparation executes within the existing Desktop turn and creates no queued message or model worker. Current-origin checks also protect batch reads and result submission, including the final before-write hook. Source, language, draft or alignment changes reject or pause affected work rather than overwriting newer drafts. Explicit native resume recaptures the unfinished context without enqueueing; cancellation preserves completed drafts and remains available after physical source drift.

Translation text size is a separate per-project display preference with a setting revision. Its 14–28 px range defaults to 17 px. The window control under More and the native preference tool share that state; delayed saves use project/revision checks and cannot overwrite another paper's preference. Body and caption text use the same base; math, editing and Compare text scale within the translation display. PDF zoom, third-column notes and metadata are outside this setting. A local fallback remains usable when storage is unavailable. Changing display size grants no draft, model, compiler, source-write or approval authority, and preserves an active editing buffer and selection.

## Explicit human formula intent

Version 1.3.0 adds an authenticated atomic paragraph save for human-authored prose and inline formula changes. It captures the project identity, source snapshot, paragraph, language and expected draft revision. Only a unique correspondence to an original protected formula can authorize an English math change. Unmapped new or ambiguous math may remain a translation draft but cannot grant source authority. The original source formula and protected token identity stay pinned to the source hash. This is not a model tool, source write or arbitrary replacement grant. The earlier exact-span formula action remains a private compatibility entry.

An edit retains the original math delimiter or environment, contains at most 32 KiB and uses validated existing or recognized mathematical controls. Executable controls, unbalanced syntax and changed embedded labels, citations, references or tags are rejected. A formula containing such anchors cannot be deleted. Complete standalone math intervals gain candidate eligibility only through independent exact-range and mathematical-structure proof. Figures, tables, arbitrary layout objects and unprovable dynamic TeX do not gain eligibility from this action.

An English-candidate request carries the authored formula as that token's effective protected value. The remaining protected objects and ordering are unchanged. Current project/source/draft checks and candidate fingerprints bind this authorization; model output cannot add formula intent or broaden it to another token or paper. Safe compilation, the compiled read set, explicit one-use human confirmation and separately compiled source undo remain mandatory.

Bounded source-pinned draft history records the exact before/after text hashes and formula-intent states. Ordinary draft undo/redo restores or deactivates matching intent through those hashes. Compatible prose edits retain current math intent; ambiguous or changed math blocks source-candidate use rather than silently authorizing another change. Original baselines remain immutable. Retranslation uses the authorized formula, while review translations for paragraphs with active human formula intent remain historical and cannot replace the current draft.

Native project authority comes from host MCP roots, a usable native launch directory, or an explicit launch binding, in that order. Model arguments and arbitrary request metadata cannot create a root or native chat identity. Empty advertised roots authorize no stale installer project. Multiple main files remain a UI choice and discovery is finite. Missing native task identity remains unavailable instead of being inferred from an MCP session ID.

The private workspace index binds task and paper identities. New records have separate state and worker chat/context roots; legacy exact bindings are indexed in place without relocating snapshots or chats. Recent history is an authenticated UI action using an opaque record ID. Active model/compiler work and pending paper operations block switching. Revoked host roots clear the active paper but preserve its history. Index writes use a separate exclusive lock and atomic replacement; malformed data and lock contention fail without deleting history.

`getState()` returns a synchronous defensive clone of this instance's latest state. Mutations reload the authoritative persisted state under the private-data writer lock before checking revisions. Refresh explicitly reloads the source graph and other-process state. Model results have strict field allowlists and server-issued request scope; a result can create a pending proposal or a derived translation only. Late translations are retained as historical results instead of replacing newer/manual drafts.

Private state is serialized across service instances with an exclusive `<dataRoot>/.write.lock` opened using `wx`. The owner token is checked before removal. Lock contention fails with `PROJECT_BUSY`; the implementation never steals a lock based on age or PID. A crash can leave the lock behind. Recovery is deliberately manual: stop all plugin/companion processes using that exact data root, preserve its state and snapshots, inspect the exact lock and state files, then explicitly remove only the verified abandoned lock before restarting. Never delete an active writer's lock. Corrupt state returns `RECOVERY_REQUIRED`; it is not silently replaced with an empty project.

Native-chat writer leases are separate from that source-state lock. The explicit native-chat recovery operation checks the exact thread lease, regular-file/path identity, owner token and a PID proven absent; unknown or live processes remain blocked. Recovering a matching local chat lock additionally requires its exact saved thread binding or the new lease's state-directory identity. It does not recover an arbitrary source-state lock or release Desktop's writer. Time alone is never a recovery authorization.

Draft/state files are written to private temporary files, flushed and renamed; an acknowledgement follows successful replacement. Failed writes preserve the in-memory pre-write state and leave the caller's edit buffer available for retry/export. Only acknowledged persisted versions are recoverable after a forced exit. No encryption-at-rest claim is made: the chosen private data directory relies on the user's filesystem access controls. Temporary files left by interrupted private writes can contain draft content and must be included in any explicitly authorized project-data cleanup.

`PaperService` remains the read/review-only core. `PaperApplication` composes it with a verified external compiler and the Windows exclusive-handle writer. Runtime capabilities become available only after the OS isolation probe passes. Immutable build identity binds exact bytes, engine, main file, source snapshot and candidate hash; the PDF hash is checked again before display and acceptance. Existing imported PDFs remain explicitly `existing-unverified` and cannot authorize source writes.

Source promotion requires a short-lived, one-use capability issued only through the authenticated UI for one exact compiled transaction. Model tools cannot prepare confirmation, apply source or create undo operations. The native writer holds FileShare.None handles for the complete compiled read set, checks final paths, single hard-link identity and bytes, then writes through those held handles. Durable before-images and a progress journal precede writes. Recovery accepts only exact old/new content; any third content freezes recovery. Undo is a separately compiled and accepted inverse transaction.

Native PDF tools use the active record and verified original/latest/current artifacts, not supplied paths. Review requests bind source/PDF/language/draft/alignment versions, expire after 30 minutes and are single-use. Stale results cannot overwrite fresh drafts. Original-only and unconfirmed-candidate reviews return opinions without replacing latest translations. Full reviews replace latest model opinions while preserving external comments; selected reviews preserve opinions outside their explicit scope. Local PDF extraction does not trigger model inference. Successful review/building establishes neither scientific correctness nor source acceptance.

Imported-review deletion is an authenticated UI action over one exact external batch, never a model tool or arbitrary filesystem path. Its five-minute one-use preview binds the project, source snapshot, target batch revision/file digest and complete associated records. Confirmation removes only that batch and its current/archived opinions under the existing state lock. Retired batches can also be deleted. The uploaded disk file, unrelated batches, drafts and formal source transaction/undo audits remain outside this operation; explicit later reimport is a fresh input lifecycle. Historical-opinion cleanup is separate and retains minimal generation heads so cleared history cannot become current again.

Preferences offer 46 common languages, English as the default interface language, and an explicit translation-language follow-interface option. Core navigation/PDF controls are localized; longer help and diagnostics may fall back to English. Localization excludes manuscript text, paths, imported notes, model messages and diffs. The light theme uses low-saturation cream surfaces with warm accents; dark mode remains selectable. Custom brand SVG/PNG/ICO assets contain no paper content and are hashed with the build; installed shortcuts reference the packaged ICO.

Immutable `originals` capture source English and an explicitly paired existing Chinese translation independently from editable drafts. Model output, candidate editing, apply and undo never overwrite these four-layer reference values. External source monitoring uses bounded known dependency paths and debounced refresh; old proposals, confirmations and PDF anchors become stale when the snapshot changes. It does not trigger background model calls.

Source/PDF navigation queries the pinned build's SyncTeX in the same OS sandbox. Current source and PDF hashes are rechecked; unpromoted candidates and stale builds cannot be used for current-source navigation. Multiple source/region matches remain choices for the author. SyncTeX provides coarse source navigation; sentence-level semantic matching and arbitrary TeX macro expansion are outside this tested MVP subset. See compiler-security.md and verification.md for current evidence and limits.
