# Translation typography and native Codex tools

The user wants equal base sizing for body and caption text in the translation column, manual size adjustment, and direct Codex plugin operations without Computer Use.

1. Reproduce the caption/headline inheritance problem with computed browser styles. Use a single translation-column size (14–28 px, default 17), preserve heading hierarchy, and scale reading math plus editable text and Compare bodies. Keep PDF, notes, metadata and controls outside that scope. Provide keyboard-accessible controls in the existing More menu.
2. Persist display preferences through per-project private workflow state with project/revision CAS, and expose them through native and UI APIs. UI selection is immediate; older acknowledgements cannot replace newer choices or another project's preference. Changing size preserves active edits and does not submit drafts or model requests.
3. Add native project-index/paragraph reads and registered selection requests. Add a native whole/selected translation task prepared for the current originating Desktop turn; existing get/submit tools consume protected batches without enqueueing another turn. Preserve bounded source reads, exact caller/project/snapshot authority, writing Skills and output validators.
4. Never expose UI tokens, source acceptance/undo confirmations, arbitrary paths or model writeback authority. Existing open/import/PDF/review/propose/compile tools remain compatible.
5. Verify focused red/green cases, relevant core/native/browser regression, real isolated native interface calls and installed-project preservation. Build/install 1.3.1, update the English handbook and package public artifacts only.

No Computer Use, new model worker, new chat, commit, push or public publication is required. A live model turn is reserved for a bounded native-interface acceptance if needed; ordinary code/browser fixtures do not send messages.
