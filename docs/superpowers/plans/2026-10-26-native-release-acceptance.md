# Native workflow and open-source preparation

## Accepted scope

Keep the existing paper, chat identity, Desktop model ownership and human confirmation boundary. The author requested a real complete translation, native review return and corresponding translation backfill, then local open-source preparation under MIT. Public uploading is a later action.

## Execution and evidence

1. Back up the exact current private paper record and source hashes outside the distributable. Inspect the installed official MCP reload method and live transport; distinguish an unavailable Desktop control socket from reconnecting the packaged MCP server.
2. Submit the complete translation through the same native action as the single workbench button. Keep one user submission and one existing Desktop turn, with protected complete batches and durable progress.
3. In the same paper chat, read the verified original/latest PDF context and return current bilingual recommendations plus permitted translations through the registered native result tool. Verify note anchors, field completeness, draft revisions, imported-note retention and unchanged source hashes.
4. Remove the PDF-context dependency on a loaded browser by preparing verified PDF text in the existing bounded local worker. Enter the serialized review context only after extraction/cache preparation; recheck the source, snapshot and exact artifact hashes before persistence. Keep current/candidate view authority unchanged.
5. Exercise isolated compilation and confirmation/undo on a disposable paper replica, with no real source promotion. Run the complete regression after relevant changes freeze.
6. Add MIT, security/contribution documentation and complete bundled-dependency notices. Produce a portable source archive from a strict allowlist, reject private inputs and aliases, and verify all archive hashes in a clean extraction/build. Keep runtime/compiler/font assets and private receipts out of the archive.

## Completion gates

Record actual results separately for the installed live model turn, synthetic/native safety checks, disposable-source transactions, browser rendering, clean source packaging and Desktop tool-catalog refresh. An unavailable control transport is not a passed hot-reload test. A successful compile is not scientific approval, and no model tool can confirm writeback or undo.
