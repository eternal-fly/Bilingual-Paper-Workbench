# Editable inline structures and responsive PDF viewing

The 1.6.0 request extends the existing three-column workbench. Authors must be able to edit inline TeX objects currently shown as locked Structure chips, type without repeated document work, and magnify a region of the English PDF without changing that file.

## Existing behavior and implementation choice

The paragraph editor makes every unrecognized protected token a noneditable chip; even a nonbreaking space (`~`) interrupts ordinary text editing. Formula and reference edits already have source-pinned author-intent protocols. PDF.js renders higher-resolution canvases, but maximum-width CSS shrinks them back into the same visible width.

Continue the established inline LaTeX editing model and extend its author-intent validation to supported inline structures. Merely unlocking a browser chip without backend support would leave saving and candidate generation broken. Removing source validation would discard the existing guarantees. The chosen implementation keeps editable author text separate from permission to publish a source edit: incomplete or unsupported input remains recoverable and receives a useful diagnostic. Model output does not acquire source-write authority.

## Required behavior

- Editable paragraph text includes inline structural notation rather than immutable generic Structure chips. Support nonbreaking spaces, escaped text and supported static inline formatting through validated source candidates. Clearly retain and explain unresolved or unsafe input; never discard it or execute arbitrary TeX.
- Continue protecting newer human input, source identity, formula/reference intent, safe candidate compilation, exact confirmation, repeated writeback and reviewed undo.
- Profile the actual input, validation, autosave and refresh path before choosing performance changes. Retain immediate live native capture, IME, caret, undo/redo, save failures and independent project state.
- Display-only PDF zoom uses a scrollable view with fit width, actual size, 25–400% controls, pointer-anchored Ctrl/wheel zoom and optional hand panning. Native scrolling and keyboard controls provide alternatives to dragging. Normal source-location clicks retain their meaning.
- Raster work is bounded independently of visible zoom. Delayed renders, cancellation, document changes and destruction must never attach an old page or point handler to a new PDF.
- Preserve the current English default interface, optional dark/cream themes, offline assets and three-column reading layout.

## Acceptance

Use only self-authored simple TeX, review notes and translated text. Exercise inline edits, formula/reference preservation, rejected unsafe input, native live draft access, repeated candidate compilation/writeback/undo and exact save/reopen. Verify PDF coordinates at different zoom levels, pointer anchoring, panning, resize/fit and unchanged PDF hashes. Run existing native/browser regressions and clean build/package checks before installing 1.6.0. Publish only audited standalone files under the existing MIT repository, with no private paper, chat, credential or local configuration data.
