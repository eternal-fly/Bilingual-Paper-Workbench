## Tested scope and remaining limits

- Version-scoped records cover both the supported bilingual XeLaTeX template and the original 18-page REVTeX paper under isolated pdfLaTeX with figures, BibTeX and retained SyncTeX. Engine/template compatibility is project-specific; this does not claim pdfLaTeX can compile the Unicode Chinese template or that arbitrary packages are supported. Verified literal reading ranges can produce protected prose candidates even in complex supported templates. Truly dynamic TeX, unsafe lexical changes and unprovable ranges remain opaque.
- Current review reads all extractable text from the exact original/latest PDF pair plus its protected paragraph index. Binary figures are not visually inspected. Scanned uploads without extractable text need external OCR. Opinions remain author-review annotations, not proofs or accepted changes. The legacy source-chunk controller remains for compatibility but is no longer used by the default UI.
- Upload capacity is 64 MiB files / 32 MiB extracted text / 5000 opinions. A complete one-turn model context has a separate 2 MiB budget; it fails explicitly if the whole pair cannot fit, without extra automatic reading prompts.
- SyncTeX gives coarse source navigation, not sentence-level semantic proof. Stale builds and unpromoted candidates cannot navigate the current source.
- The compiler uses OS process isolation with bounded CPU, memory, wall time and output monitoring. Output space is sampled every 50 ms, rather than enforced by a hard volume quota. The install-owned public runtime has read/execute access for AppContainers; private sources and job data do not.
- The paper chat uses normal Codex sign-in and its live model catalog. Model availability is checked without automatic fallback. Its model has no environment execution tools; the Codex process itself is not claimed to have a restricted-read OS sandbox.
- One client owns the paper chat writer. An idle explicit release returns that exact chat for another client without deleting history or stopping unrelated Desktop tasks. Native-chat recovery can remove only precisely verified dead-owned leases and matching chat locks; unknown/live/malformed locks remain blocked. Source-state recovery remains separate. No lock is stolen by timeout.
- Private state relies on user filesystem access controls; no encryption-at-rest claim is made. Manual screen-reader review and broad performance percentiles have not been established.

Historical installed-package checks and private screenshots retain their recorded version scope. The final 1.0 artifact/installation and Desktop-window-close gates remain tied to the receipt at the top of this document. A window-close test, if completed, does not imply operation after every required background process or runtime has been terminated.
